# دليل تشغيل نظام "دكتور" (Doctor) 📱🩺
### نظام إدارة سنتر الموبايلات والمبيعات والصيانة المتكامل

نظام ويب احترافي وشامل مبني بتقنيات **ASP.NET Core (.NET 10)** و **Entity Framework Core Code First** مع قاعدة بيانات **Microsoft SQL Server Express**، وواجهات مستخدم عربية كاملة (RTL) باستخدام **Bootstrap 5 RTL**, **Chart.js**, **JsBarcode**, و **Html5Qrcode**.

---

## 🌟 مميزات النظام

### 1. 👥 الأمان والصلاحيات (Users & RBAC)
- 3 أدوار رئيسية مثبتة: **المدير العام (Admin)**، **مسؤول المبيعات والكاشير (Sales)**، **فني الصيانة (Maintenance)**.
- نظام أذونات تفصيلي (21 صلاحية دقيقة) لإدارة كل شاشة وعملية.
- تشفير آمن لكلمات المرور باستخدام PBKDF2 المدمج في ASP.NET Core Identity.
- سجل تدقيق ومراقبة الحركات (Audit Logs) يسجل المستخدم، العملية، التاريخ، وعنوان الـ IP.

### 2. 📊 لوحة تحكم الإدارة (Admin Dashboard)
- مؤشرات أداء فورية (KPI Cards): مبيعات اليوم والشهر، أرباح الصيانة، الأجهزة قيد الإصلاح، ونواقص المخزن.
- رسوم بيانية تفاعلية (Chart.js): مبيعات الـ 7 أيام الأخيرة، وأكثر الأجهزة صيانة.
- تقارير شاملة قابلة للتصدير والطباعة: تقرير المبيعات والأرباح، تقرير الصيانة، تقرير تقييم المخزون.
- إعدادات النظام وتخصيص بيانات المتجر وروابط الـ WhatsApp API.

### 3. 🛒 نقطة البيع والمخازن (POS & Sales Dashboard)
- شاشة كاشير سريعة مع تقسيم احترافي (المنتجات يمين والسلة يسار).
- دعم قارئ الباركود اللاسلكي/السلكي (Hardware Scanners) عبر كشف نبضات الإدخال السريعة.
- دعم كاميرا الموبايل/اللابتوب لمسح الباركود مباشرة عبر مكتبة `html5-qrcode`.
- خصم فوري من المخزون المركزي مع تسجيل حركة تدقيق في جدول `InventoryTransactions`.
- فاتورة بيع متوافقة مع الطابعات الحرارية (80mm Thermal Receipt) مع كود QR للفاتورة.
- إدارة المنتجات، الأجهزة بأرقام المسلسل/الـ IMEI، والإكسسوارات مع تنبيهات النواقص.

### 4. 🔧 لوحة تحكم الصيانة (Maintenance Dashboard)
- دورة حياة الصيانة عبر 8 مراحل دقيقة:
  1. `تم الاستلام` (Received)
  2. `قيد الفحص` (Under Inspection)
  3. `بانتظار موافقة العميل` (Pending Customer Approval)
  4. `تمت الموافقة / جاري الإصلاح` (Approved / In Progress)
  5. `تم الإصلاح بنجاح` (Repaired)
  6. `تعذر الإصلاح / مرفوض` (Cannot Be Repaired / Rejected)
  7. `جاهز للتسليم` (Ready For Pickup)
  8. `تم التسليم للعميل` (Delivered)
- معالج استقبال أجهزة الصيانة (Device Reception Wizard) يسجل العميل، الجهاز، الرقم التسلسلي/IMEI، العطل، الملحقات، التكلفة المتوقعة، والدفعة المقدمة.
- كود تتبع فريد لكل طلب صيانة (مثال: `REP-2026-00001`).
- ربط واستهلاك قطع الغيار مباشرة من مخزون الصيانة وحساب أرباح الصيانة تلقائياً.
- إيصال استلام صيانة حراري للعميل مزود بباركود التتبع.

### 5. 🏷️ نظام الباركود والملصقات الحرارية (Barcode Generator & Printing)
- توليد وتصميم ملصقات باركود حرارية للمنتجات (50x30mm) تتضمن اسم المحل، اسم المنتج، السعر، وكود الباركود (Code128).
- شيت طباعة ملصقات متعددة بنقرة زر واحدة.

### 6. 👤 ملف العميل الموحد (Unified Customer 360)
- ملف تعريفي يربط العميل برقم الهاتف.
- سجل كامل لمشتريات العميل من نقطة البيع.
- سجل كامل لأجهزة الصيانة الخاصة بالعميل وحالاتها.

### 7. 💬 تكامل رسائل الواتساب (WhatsApp Notifications)
- إرسال إشعارات تلقائية للعميل عند استلام الجهاز وتحديث حالة الصيانة.
- دعم العمل بوضعين:
  - وضع البوابة البرمجية (API Gateway) في حال توفر مفتاح API.
  - وضع التوليد الفوري لروابط `wa.me` بنص الرسالة الجاهز للإرسال بنقرة واحدة بدون تكلفة إضافية.

## 🛠️ متطلبات التشغيل (Prerequisites)

1. **NET 10.0 SDK.** أو أحدث.
2. **Microsoft SQL Server 2019/2022 أو SQL Server Express**.
   - الاتصال الافتراضي في `appsettings.json`:
     ```json
     "ConnectionStrings": {
       "DefaultConnection": "Server=.\\SQLEXPRESS;Database=DoctorCenterDb;Trusted_Connection=True;TrustServerCertificate=True;MultipleActiveResultSets=true;"
     }
     ```

## 🚀 خطوات التشغيل (Getting Started)

### 1. الدخول إلى مجلد المشروع
```bash
cd "d:\االدكتور"
```

### 2. تحديث وتجهيز قاعدة البيانات (Database Migrations & Seeding)
يقوم النظام تلقائياً عند أول تشغيل بإنشاء قاعدة البيانات `DoctorCenterDb` على SQL Server وحقن البيانات التجريبية الأولية.
كما يمكنك تطبيق الـ Migrations يدوياً عبر:
```bash
dotnet ef database update --project Doctor.Web/Doctor.Web.csproj
```

### 3. تشغيل التطبيق
```bash
dotnet run --project Doctor.Web/Doctor.Web.csproj -c Release --urls "http://localhost:5000"
```

افتح المتصفح على:
👉 **[http://localhost:5000](http://localhost:5000)**

## 🔑 الحسابات التجريبية الافتراضية (Default Credentials)

تم تهيئة 3 حسابات رئيسية جاهزة لتجربة الصلاحيات المختلفة:

| الدور (Role) | اسم المستخدم (Username) | كلمة المرور (Password) | الصلاحيات والوصول |
| :--- | :--- | :--- | :--- |
| **المدير العام (Admin)** | `admin` | `Admin@123` | وصول كامل لكافة اللوحات، الإعدادات، التقارير، الصيانة، والمبيعات |
| **مسؤول المبيعات (Sales)** | `sales` | `Sales@123` | الوصول لنقطة البيع (POS)، الفواتير، والمنتجات |
| **فني الصيانة (Maintenance)** | `tech` | `Tech@123` | الوصول للوحة الصيانة، استلام الأجهزة، وتحديث حالات الإصلاح وقطع الغيار |

## 📁 هيكلية المشروع (Project Architecture)

```
d:\االدكتور\
├── Doctor.sln
└── Doctor.Web/
    ├── Controllers/             # وحدات التحكم (Admin, Sales, Maintenance, Customers, Barcode, Api, Account)
    ├── Data/
    │   ├── ApplicationDbContext.cs  # إعداد الجداول والعلاقات بـ EF Core Fluent API
    │   ├── DbInitializer.cs         # حقن الأدوار والمستخدمين والمنتجات التجريبية
    │   └── Migrations/              # ملفات الـ Migrations المنفذة
    ├── Models/
    │   ├── Entities/            # كائنات النطاق (User, Product, Sale, RepairOrder, Customer, ...)
    │   └── ViewModels/          # نماذج العرض للواجهات
    ├── Services/                # طبقة منطق الأعمال (Auth, Pos, Repair, Inventory, WhatsApp, Barcode, Reports)
    ├── Views/                   # واجهات Razor العربية الكاملة (Admin, Sales, Maintenance, Customers, Barcode)
    ├── wwwroot/
    │   ├── css/site.css         # تصميم Cairo Font، تنسيقات الفواتير والطباعة الحرارية
    │   └── js/site.js           # مسح الكاميرا، استشعار قارئ الباركود، التنبيهات
    ├── Program.cs               # تكوين الخدمات، التوثيق، وسير العمل
    └── appsettings.json         # سلاسل الاتصال وإعدادات المتجر
```
